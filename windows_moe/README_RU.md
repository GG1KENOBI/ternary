# Сравнить три MoE на Windows 10 и RTX PRO 6000 Blackwell

WSL, Ubuntu, PyTorch и CUDA Toolkit не нужны. Нужны Windows x64,
обычный Python 3.10+ x64, интернет и драйвер NVIDIA.
Обучение не запускается: сравниваем готовые Q8-модели на одной карте.

## Скачать и начать

1. Обновите вашу копию `GG1KENOBI/ternary` через `git pull --ff-only`.
   Или скачайте весь репозиторий: GitHub → Code → Download ZIP, затем распакуйте.
   Папка `demo/` тоже нужна — в ней задания и тексты. Один `compare.py` отдельно не копируйте.
2. Откройте папку `windows_moe` и запустите **`check.bat`** двойным щелчком.
   Если Python не установлен, установите x64-версию с
   [python.org](https://www.python.org/downloads/windows/), включив Python Launcher / Add to PATH.
   Python-пакеты через pip устанавливать не нужно.
3. После успешной проверки запустите **`run.bat`**. Он проверит **GigaChat → Gemma → Qwen**,
   по одной модели за раз, на всех 10 заданиях. После успешного прогона модели и остановки
   сервера её веса удаляются. При ошибке веса сохраняются и весь запуск останавливается.

По умолчанию используется **GPU 1** — одна из показанных вами свободных карт.
Номер берётся из `nvidia-smi`. Чтобы выбрать другую карту, откройте CMD в этой папке:

```bat
run.bat --gpu 2
```

На проверке `check.bat` скачиваются только программа и её DLL (~0,59 ГБ), **без моделей**.
Сборка закреплена: llama.cpp **b11960**, Windows x64, **CUDA 13.4**,
официальные архивы с проверкой SHA256. CUDA 12.4 для Blackwell не выбирается.
Скрипт проверяет драйвер ветки **580+**, затем реальное обнаружение карты программой.
Драйвер 580+ — необходимая предварительная проверка, а не гарантия совместимости всех DLL/PTX:
решающим остаётся запуск. Если программа не видит GPU, веса не скачиваются.
Драйверы, ОС и режим MCDM скрипт не меняет.
При ошибке отсутствующей `VCRUNTIME` / `MSVCP` нужен официальный
[Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe).

## Модели, место и скачивание

| Порядок | Модель | Файл Q8 | Размер файла |
|---|---|---|---|
| 1 | GigaChat 3.1 Lightning | официальный ai-sage GGUF | 11,35 ГБ |
| 2 | Gemma 4 26B-A4B-it | unsloth GGUF | 26,86 ГБ |
| 3 | Qwen3.6-35B-A3B | unsloth GGUF | 36,90 ГБ |

Всего через интернет загрузится около **75 ГБ** весов. На диске одновременно одна модель:
рекомендуется **45 ГБ свободного места** на диске с репозиторием.
Окружение и программа занимают дополнительное место. Нужен NTFS/exFAT;
FAT32 не подходит для таких файлов. Скорость интернета сильно влияет на общее время.
Оценку времени самих заданий получим на ваших картах; обещаний «всё за час» нет.

Точные ревизии, размеры, SHA256, репозитории и заявленные лицензии закреплены в `models.json`.
Модели публичные; если Hugging Face потребует вход или принятие условий,
ошибка сохранится в отчёте. Секретные ключи скрипту не передаются.

Скачивание идёт в служебную папку `_models` внутри комплекта. Только этими весами скрипт
управляет: старые модели, кеш Hugging Face и файлы вне комплекта не удаляются.
После успешного скачивания сначала проверяется SHA256. После успешного прогона останавливается
только запущенный этим скриптом сервер, затем удаляется проверенная модель.
Если загрузка сервера, проверка GPU или запрос завершились ошибкой, веса остаются:
повторный запуск проверит их SHA256 и использует без нового скачивания.
Другие процессы llama.cpp не завершаются.

При обрыве сети или Ctrl+C во время скачивания остаётся `.part`:
повторный запуск продолжит загрузку той же версии. Для паузы используйте Ctrl+C,
а не закрытие окна крестиком. Если закрыть окно принудительно, программа может
не успеть остановить сервер и удалить веса; это видно в Диспетчере задач.
Одновременный второй запуск блокируется файлом `_run.lock`. Если после принудительного
закрытия он остался, сначала убедитесь, что предыдущие `compare.py` и его сервер остановлены,
и только затем удалите `_run.lock` вручную.

## Что именно сравниваем

- 10 заданий из `demo/tasks.json`: пересказ четырёх размеров, вопрос по тексту,
  JSON из письма, деловой стиль, перевод, отзывы и письмо клиенту.
- Одна и та же инструкция, температура 0, seed 13, контекст 32 768, один запрос за раз.
  Шаблон чата берётся из GGUF **каждой модели**, без подстановки шаблона Qwen для всех.
- Рассуждения выключены и на сервере, и в запросах. Это тест обычных ответов ассистента,
  не сравнение максимально возможного reasoning-качества.
- Сохраняются полные ответы, исходные JSON-ответы сервера, причины остановки,
  время запроса, серверные скорости и выборка занятой видеопамяти раз в две секунды.
  Память — общая по выбранной карте, включая возможные посторонние процессы.
- Кеш запросов и сдвиг контекста выключены. Превышение контекста считается ошибкой,
  а не незаметным обрезанием текста. Достижение лимита ответа отмечается в отчёте.
- Проверяется полная выгрузка слоёв на GPU по логу уровня 4. Запуск на CPU не выдаётся за GPU-замер.
  Ошибка архитектуры, DLL, загрузки или запроса останавливает весь запуск на первой проблеме,
  сохраняя веса и результаты. Ошибка скачивания сохраняет `.part`.

## Результаты

В конце выводится путь `windows_moe/results/<дата-время-суффикс>.zip` — **пришлите этот ZIP**.
В нём нет весов. Есть `results.json`, читаемый `answers.md`, информация об оборудовании,
параметры и логи каждого сервера. Результат сохраняется после каждого задания,
архив создаётся и при ошибке. Сначала качество оцениваем по ответам и фактам;
скорость на GPU не говорит о скорости на вашем i3.

Если нужна только маленькая проба (скачает только GigaChat, ~11 ГБ):

```bat
run.bat --models giga --tasks sum_short extract
```

Другие варианты:

```bat
run.bat --plan
run.bat --models gemma
run.bat --keep-models
run.bat --server C:\llama-cuda\llama-server.exe --check
```

`--plan` только печатает план, без сети и запуска. `--keep-models` отменяет удаление;
это требует места под сумму весов выбранных моделей.
`--server` позволяет указать свою совместимую CUDA-сборку (например, CUDA 12.8+),
но совместимость архитектур всё равно проверяется фактической загрузкой.

## Проверки комплекта

Тесты не скачивают модели и не запускают нейросети:

```bat
py -3 -m unittest discover -s tests -v
```

Проверяются HTTP-загрузка с продолжением и SHA256, шаблоны запросов, обработка ошибок,
остановка своего сервера до удаления весов и сохранение отчётов.
Работа настоящих моделей на вашем Blackwell остаётся отдельным пользовательским запуском.

Исправление 30.10, версия `2026-10-30.2`: в b11960 обычный уровень лога 3 скрывает
библиотечную строку `offloaded N/N`. Теперь уровень 4 задаётся явно и проверяется
в Windows CI сквозным тестом с маленькой моделью 260K (~1,2 МБ) на CPU.
Это проверяет реальный лог и API, но не заменяет замер больших MoE на GPU.
