# Пробный запуск на RTX PRO 6000 Blackwell 96 ГБ

Передача комплекта — через приватный репозиторий `GG1KENOBI/ternary`.
Запускаете вы на своём ПК. Удалённый доступ и аренда не нужны.
Первый опыт — короткое обучение, а не полный многодневный прогон.
MoE пока не поддерживается нашим TED: здесь проверяем существующий рецепт на обычной 4B.

## 1. Открыть Ubuntu (WSL2)

В PowerShell посмотрите `wsl -l -v`. Нужна Ubuntu с VERSION 2.
Если её нет, в PowerShell от администратора выполните:

```powershell
wsl --install -d Ubuntu-24.04
```

Если Windows попросит перезагрузку, перезагрузите ПК и откройте Ubuntu.
Дальнейшие команды выполняются **в Ubuntu**, не в PowerShell и не в Git Bash.
Внутри Ubuntu проверьте `nvidia-smi`: карты должны быть видны и здесь.
MCDM сам по себе не требует смены режима: доступ из WSL зависит от версий Windows,
WSL и драйвера. Скрипты не меняют режим карт и драйвер.
Если карт в Ubuntu нет, пришлите вывод `wsl -l -v`, `wsl --version` из PowerShell
и `nvidia-smi` из обоих окружений; обучение пока не запускайте.

Не устанавливайте Linux-драйвер NVIDIA внутрь WSL. Используется драйвер Windows.

## 2. Скачать или обновить код

Если репозиторий уже есть в домашней папке Ubuntu:

```bash
cd ~/ternary
git pull --ff-only
```

Для новой копии (нужна авторизация в приватном GitHub-репозитории):

```bash
cd ~
git clone https://github.com/GG1KENOBI/ternary.git
cd ternary
```

Можно вместо git скачать ZIP через браузер под своим GitHub-аккаунтом и распаковать
его в домашнюю папку Ubuntu. Это также подходит при проблемах с авторизацией git.
Рабочую папку и модели лучше держать в файловой системе Ubuntu, не в `/mnt/c`.
Скачивание пакетов, моделей и датасетов требует интернета.

## 3. Установка и проверка карт

Если `uv` ещё не установлен:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
```

Затем из корня репозитория:

```bash
cd release
bash setup_blackwell.sh
```

Создаётся отдельная `.venv-blackwell` (Python 3.12, PyTorch 2.9.1 с CUDA 12.8,
Transformers 5.19.0, FLA). Старое `.venv` не меняется. Версии пакетов записываются
в `blackwell-results/packages.txt`. Не нужны CUDA Toolkit и сборка llama.cpp.
Установка не запускает обучение и не скачивает веса моделей.
Проверка выполняет маленькое матричное умножение bf16 с обратным проходом на каждой
видимой карте и записывает `blackwell-results/hardware.json`.
Если она упала, пришлите этот файл; к следующим шагам не переходите.

## 4. Короткий тест TED на одной карте

В примере используем карту с индексом **1 в Ubuntu**. Индексы сначала проверьте
через `nvidia-smi`; если карта занята, выберите другую свободную.

```bash
CUDA_VISIBLE_DEVICES=1 bash pilot_blackwell.sh smoke
```

Это SmolLM2-135M, 131 тыс. токенов: загрузка, тернаризация TED-16, дистилляция,
обратный проход, сохранение, загрузка результата и оценка. Проверяет работоспособность,
не качество русского ассистента. Внутри процесса выбранная карта станет `cuda:0`.

## 5. Пилот 4B с диалогами

После успешного smoke:

```bash
CUDA_VISIBLE_DEVICES=1 bash pilot_blackwell.sh pilot4b
```

Qwen3.5-4B, 2 млн токенов, TED-16 + учитель + OFF, блок 256 + поворот 256,
смесь русских/английских текстов и диалогов. Batch 2, контекст 512.
Нужно минимум 50 ГБ свободного места (включая кеш модели и точки сохранения;
если HF_HOME вынесен на другой диск, проверьте свободное место и там).
Модель скачивается один раз в стандартный кеш Hugging Face, данные готовятся заново
в папке конкретного прогона. На карте 96 ГБ ожидается запас, но реальный пик
и скорость установим именно этим тестом. Короткий пилот ещё не доказывает качество готовой модели.

Если FLA не загружается, Qwen может использовать медленный путь PyTorch.
Первый запуск также может тратить время на компиляцию Triton — это попадёт в лог.
Если будет ошибка или долго нет прогресса, пришлите `console.log`, не запускайте параллельно второй процесс.

## 6. Отдельно проверить несколько карт

Только после успешного запуска на одной карте:

```bash
CUDA_VISIBLE_DEVICES=1,2 TED_NPROC=2 bash pilot_blackwell.sh ddp-smoke
```

Это снова маленькая SmolLM2, а не 4B. Проверяется NCCL и совместное обучение.
Карты должны быть видны в Ubuntu. Проверку связи на WSL считаем отдельным опытом:
ошибка NCCL не означает, что обучение на одной карте не работает. Скрипт завершится
с ошибкой, если существующая проверка TED обнаружит расхождение состояний карт.
Третью карту добавим после этих замеров; показанный вывод Windows содержит карты 1 и 2,
а состояние карты 0 пока неизвестно.

## Что прислать

Каждый запуск создаёт новую папку `release/blackwell-results/<режим>-<время>-<суффикс>`.
В конце печатается её путь. Старые результаты не удаляются и не продолжаются автоматически.
Пришлите `console.log`, `hardware.json`, `packages.txt`, `eval.json` (если создан),
`distributed.log` (для нескольких карт)
и `train/log.jsonl` (если создан). Веса, данные и многогигабайтные `ckpt.pt` не нужны.
Если останавливаете Ctrl+C, последняя завершённая точка остаётся в `train/ckpt.pt`;
сам запуск через этот скрипт всегда создаёт новую папку.

Полное обучение 9B/27B и выбор MoE — следующие отдельные опыты после этих результатов.
